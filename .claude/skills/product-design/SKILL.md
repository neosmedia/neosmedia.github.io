# Product design

Always read `DESIGN.md` at the repo root first; it defines tokens, type, shapes and motion.

## Approach
1. Start from the problem and the audience (hiring managers, founders, freelance clients), not the layout.
2. Reuse existing tokens and components before inventing new ones. No new colours, fonts or radii without updating `DESIGN.md`.
3. Design light and dark together.
4. Prefer fewer elements, larger type, more space. One accent at a time.
5. Keep the hero playful and everything below it calm.

## Case-study structure (for /work/<slug> pages)
Context (role, dates, team) -> Problem -> Constraints -> Process (key decisions, not every step) -> Solution (annotated visuals) -> Outcome (metrics or qualitative result) -> What I'd do next.
Subtitle style on cards: short, descriptive, no period (e.g. "Remote Equipment Monitoring").

## Checklist before handing off
- Matches `DESIGN.md` tokens, radii, type roles.
- Works at 375px and 1440px, light and dark.
- Copy: sentence case, "&" in titles, curly apostrophes, no trailing periods on headings.
- Motion uses easing/physics; respects reduced motion.
